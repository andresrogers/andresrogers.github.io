Pricing · Elasticity & optimization

Airbnb price-demand elasticity and MILP price optimization

Predicting occupancy is not the deliverable. The deliverable is a price schedule that maximizes annual revenue under business constraints.

End-to-end PySpark pipeline: exploratory analysis and segment-level price elasticity, feature engineering including elasticity slopes, model comparison for occupancy rate, then Mixed-Integer Linear Programming with PuLP to optimize price across 6 segments (3 seasons × weekday/weekend), combining ML-predicted baseline occupancy with regime-aware elasticity curves.

  • R² 0.885 Best occupancy model, GBTRegressor (RMSE 0.0786, MAE 0.0599), ahead of PyTorch MLP 0.876, linear regression 0.854, random forest 0.851, TensorFlow/Keras MLP 0.815
  • +4.5% Simulated annual revenue lift for one Paris listing profile: 30,215 baseline to 31,560 optimized, under ±50% price bounds and a 50% minimum-occupancy constraint
  • +14.1% Largest segment lift, high-season weekend; weighted average price 107.23 to 129.89, average occupancy 75.5% to 65.0%

Results are simulated on a public Airbnb dataset, not a production deployment.

FinOps · Commitment optimization

AWS commitment sizing: Savings Plan optimization on anonymized cost data

Decide how much AWS spend to cover with Savings Plans or Reserved Instances. Commit too little and savings are left on the table; commit too much and unused hours are still billed as waste.

DuckDB over 20,901,528 hourly usage rows and 10,955 pricing rows from one anonymized AWS organization with multiple linked accounts, complete months 2025-07 to 2026-05. Data-readiness checks, a savings bridge (commitment discount, Spot savings, unused-commitment waste, reconciliation), and an exact optimizer that allocates commitment hour by hour, highest discount first, at every commitment breakpoint. Followed by window-sensitivity analysis, a baseline backtest, an audit of 29 existing commitments, and a coverage/utilization frontier.

  • 11.52% Effective savings rate today: $111,028.43 net savings against $963,836.65 on-demand equivalent, complete months only
  • $23.14/h Optimal 3-year Compute Savings Plan on the latest 3 complete months: $38,581.82 savings, 99.41% utilization, 94.05% coverage
  • $21.51/h Recommended operating point, the highest-utilization point within 95% of peak savings: $37,156.94 savings, 100.00% utilization, 88.77% coverage, against a current posture of $19.46/hour

Retrospective analysis of one organization's real-but-anonymized AWS cost data.

Generative AI · RAG & evaluation

LangChain RAG for clinical trials (defensible ground-truth workflow)

Answer clinical-trial questions with grounded, citable evidence across heterogeneous sources, and produce evaluation-grade annotations.

Ingests AACT metadata, PubMed and PMC publications (XML and PDF), and FDA drug labels. Section-aware hybrid chunking preserves filename, page, section title, NCT id and PMID for precise citations. Embeddings are persisted into a Chroma vectorstore holding 5,532 indexed chunks (PDF approx. 1,411, PubMed XML approx. 305, FDA labels approx. 3,816); the master clinical-trials table covers 127 Phase III trials. Retrieval combines dense embeddings with BM25 and optional cross-encoder reranking; ground truth follows an extractive draft, human review, refined answer pipeline; generation quality is scored with RAGAS using a judge model.

  • 0.972 Faithfulness (RAGAS, n = 10 evaluation questions)
  • 0.901 Factual correctness F1 (RAGAS, n = 10)
  • 0.900 Context recall and answer relevancy (RAGAS, n = 10)
  • 0.733 Context precision (RAGAS, n = 10): remaining room to cut noisy context

Public-data portfolio project. RAGAS scores come from an evaluation sample of 10 questions, which bounds how far they generalize.

Clinical data science · Phase I to III

NTX-101: sponsor-style clinical development portfolio

Simulate a full Alzheimer's development program with standards-aware structure, traceable derivations, and explicit decision gates instead of isolated descriptive plots.

CDISC-shaped public structure with a bounded synthetic continuity bridge: raw XPT/RDA to interim parquet to harmonized SDTM-like domains to ADaM-like analysis datasets to gated reports. 12 CDISC Pilot XPT domains and 32 SafetyData RDA objects normalized into parquet, ADaM-like ADSL, ADAE, ADLB, ADVS, ADEFF and ADTTE outputs, formal treatment-vs-placebo comparisons, survival analysis, and an interpretable logistic regression primary model benchmarked against elastic net and random forest. A thin R reference layer cross-checks selected derivations.

  • 0.868 Phase II ROC AUC, logistic regression primary model
  • 19.07 pp Phase II responder uplift, primary endpoint p = 0.0019
  • 83.58 d Phase III median delay to worsening, log-rank p = 0.0421

NTX-101 is a fictional investigational asset. The data combine a public CDISC structure with a synthetic continuity bridge. This is portfolio simulation work: not sponsor production, not GxP validated, and not regulatory evidence.

03 · Agentic AI engineering

Multi-agent workflows with independent verification

I design multi-agent workflows for production software engineering and data science, with emphasis on orchestration, task decomposition, controlled autonomy, independent verification, and human-in-the-loop decision making.

Typical orchestration pattern

  1. 01

    Scout

    Explores repositories, dependencies, data flows, APIs, documentation, and relevant system context.

  2. 02

    Architect

    Designs the solution, defines interfaces, identifies risks, and decomposes work into bounded tasks.

  3. 03

    Engineer

    Performs scoped implementation against explicit requirements and acceptance criteria.

  4. 04

    Reviewer

    Independently analyzes diffs, assumptions, tests, regressions, edge cases, and architectural consistency.

  5. 05

    Judge

    Evaluates implementation evidence and reviewer findings against acceptance criteria, then returns one verdict.

    • PASS
    • REVISE
    • REJECT
    • ESCALATE
  6. 06

    Human

    Retains final authority over ambiguous, high-risk, or production-impacting decisions.

How throughput is controlled

I use parallel Git worktrees, subagent delegation, context isolation, model routing, MCP integrations, structured outputs, automated validation, quality gates, guardrails, and escalation rules to improve throughput without treating LLM output as inherently correct.

The objective is not maximum autonomy. It is maximum useful autonomy with inspectability, independent verification, and minimum risk.
